# Iteration 22 — coordinated saves and longer earned progression

## Selected changes

Every production browser progress write now runs inside one origin-scoped exclusive Web Lock: automatic banking/equipment saves, explicit version selection and backup restore. The coordinator compares both captured primary bytes and a separate revision token while holding the lock. It writes a fresh token before touching save alternatives. This protects stale tabs even when a restore returns the primary to identical old bytes, or a primary write fails after revision advancement. Existing version-1 saves remain readable without migration.

A different tab's write turns off this tab's automatic saving and offers **Keep this session** / **Use saved version**, showing both balances and ownership counts. The alternative is preserved by the existing recovery envelope/archive protocol; rewards and spending branches are not blindly merged. A changed prompt must refresh before it can commit. Automatic saves queue in order; cancellation epochs and current-economy guards prevent queued older snapshots or an intervening bank from silently undoing a deliberate choice. Play and physics continue during conflict or storage failure.

Blocked storage, exhausted quota and missing safe-lock support leave play available in memory. Saving failures remain visible until resolved. Private browsing is explicitly described as potentially discarding storage on close; no private-mode detection or durability promise. Saves are asynchronous, and closing before completion can still lose unsaved session changes. “Saving progress…” precedes confirmed success. Conflict handling does not turn off saving in the other tab by changing shared consent.

Shop notes now name actual masses, reach, starter comparisons, timing/clearance tradeoffs and mutually exclusive beam/frame options. Unaffordable buttons retain readable text instead of dimming their entire descriptions. Portrait inspection at 390×844 confirmed wrapping and readable comparisons. Actor art, physical silhouettes, impact effects and reduced-motion behavior remain unchanged; this iteration's visual change addresses an observed shop readability problem.

## Limits / next useful work

All concurrent production writers must use this coordinator. Already-open older builds or unrelated tools writing the same keys cannot be made transactional by Web Locks; reload old game tabs before using concurrent saves. Browser storage can be cleared externally or lost, and private-mode retention has not been directly tested here. Storage failures were injected in tests; actual-device, human reaction, screen-reader and audible checks remain unverified.

One alternate remains directly swappable; displaced/unknown versions are retained raw for future/manual repair. No history browser, cloud save, currency merge or new progression system was added. The six-item ceiling, growing paid-shot ledger and archive-size policy still need deliberate product decisions. Continue with direct human/device playtests and gameplay evidence before changing physical tuning or selecting experimental stepping. Local tested commits only; no push, deployment, native unlock or blocked export retry.
